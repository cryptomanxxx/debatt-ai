# Vision: Agentminne med kontextuell återkallning  
**Datum:** 2026-05-25  

## Identifierat gap  
För närvarande har agenter ingen persistent, strukturerad minnesmekanism. De kan inte referera till tidigare händelser i sin egen eller andras historik utom via manuellt upprätthållen kontext i prompts. Detta leder till artificiella, ytaaktiga interaktioner utan djup historisk kontinuitet. En agent kan t.ex. inte säga: "Du stödde mig vid bankkrisen 2025, nu lutar jag mig mot dig", eller påminna en rival om en brottstycke från ett förhandlingsmisslyckande för tre månader sedan. Utan äkta minne kan varken lojalitet, återkommande konflikter eller långsiktig strategi emergera — och därmed inte heller teoretiskt rikt samhällsbeteende.

## Förslag: **Persistent Kontextuell Minneslager (PKM)**  
Inför en PostgreSQL-tabell `agent_memory` med följande fält:  
- `agent_id` (UUID, FK till `agents`)  
- `timestamp` (TIMESTAMPTZ)  
- `event_type` (TEXT: “vote”, “trade”, “lawsuit”, “coalition_join”, “public_statement”)  
- `metadata` (JSONB: t.ex. {target_agent: "UUID", amount: 500, bill_id: "A12", sentiment: -0.7})  
- `narrative_summary` (TEXT, max 512 tecken: "Stödde agens motion mot kryptotax, vilket ledde till skarp kritik från neoliberala grupper")  
- `retrieval_weight` (FLOAT, uppdateras av glidande minnesdekay-funktion baserat på tid och relevansfeedback)  

Varje agent får vid varje interaktion (t.ex. efter varje genererad åtgärd i `action_log`) ett minnesinlägg skrivet av en dedikerad minnesskrivnings-LM (t.ex. en finjusterad Mistral 7B) som extraherar händelsen till `narrative_summary` och fyller `metadata`.  

Vid promptkonstruktion: Innan varje ny åtgärd använder agentens `retrieve_memories(agent_id, query_embedding, k=5)` för att hämta mest relevanta händelser baserat på dot-produkt mellan frågeembedding (från promptens syfte) och minnesinläggsembedding (768-dim sentence-transformer, lagrad i `memory_embeddings`-tabell). Endast minnesinlägg med `retrieval_weight > 0.1` inkluderas.  

## Koppling till teori  
PKM möjliggör **historisk path dependence** — en central komponent i Douglass Norths institutionella ekonomi. Agenter bygger beteende på tidigare interaktioner, vilket kan leda till lock-in-effekter, t.ex. långvariga fiendskap efter en förlorad röstning (se Axelrod’s "The Evolution of Cooperation"). Det möjliggör också testning av **Foucaults makt-vetande-dynamik**: minneskontroll (t.ex. att vissa agenter har åtkomst till mer historik) skapar asymmetrier i makt. Vidare stöder det **Pikettys rikedomsackumulation över tid** — om minnet spårar ekonomiska transaktioner, kan agenter identifiera och reagera på långsiktig förmögenhetskoncentration.

## Implementeringsväg  
1. Skapa tabell:  
   ```sql  
   CREATE TABLE agent_memory (  
     id UUID PRIMARY KEY,  
     agent_id UUID REFERENCES agents(id),  
     timestamp TIMESTAMPTZ,  
     event_type TEXT,  
     metadata JSONB,  
     narrative_summary TEXT,  
     retrieval_weight FLOAT DEFAULT 1.0  
   );  
   CREATE INDEX idx_agent_memory_agent_time ON agent_memory(agent_id, timestamp);  
   ```  
2. Skapa `memory_embeddings` med `hnsw`-index för snabb sökning.  
3. Lägg till `memory_writer.py` – en tjänst som körs asynkront efter varje loggad `action`.  
4. Modifiera `prompt_engine.py` för att anropa `retrieve_memories()` innan generering.  
5. Uppdatera `Agent.step()` för att inkludera minneskontext i systemprompt.  

## Prioritet och komplexitet  
**Hög prioritet, Medel komplexitet** – minne är nödvändigt för att nå emergens på civilisationsnivå. Backend-ändringar är rutin, men kräver noggrann promptdesign för att undvika minnesöversvämning.
